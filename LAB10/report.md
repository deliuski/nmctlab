## Алхам 2: Alarm сүлжээний бүтэц

> Шалгах: Задаргаа P(B) P(E) P(A | B, E) P(J | A) P(M | A) гарна. Бүтэн хүснэгт 31, сүлжээ 10 параметртэй (1 + 1 + 4 + 2 + 2). Яагаад ийм их ялгаа гарч байгааг "хувьсагч бүр цөөн эцэгтэй" гэсэн санаагаар тайлбарла.

Сум: B -> A, E -> A, A -> J, A -> M.

Хамтарсан магадлалын задаргаа:

P(B, E, A, J, M) = P(B) \* P(E) \* P(A | B, E) \* P(J | A) \* P(M | A)

Параметрийн тоо:

* Бүтэн хамтарсан хүснэгт: 2^5 - 1 = **31**
* Сүлжээ: P(B)=1, P(E)=1, P(A|B,E)=4, P(J|A)=2, P(M|A)=2, нийт **10**

CPT-ийн хэмжээ 2^(эцгийн тоо) байдаг тул бүх хувьсагчийг хамтад нь хадгалахаас хамаагүй бага болдог. Хувьсагчийн тоо нэмэгдэх тусам бүтэн хүснэгт хурдан өсдөг, харин сүлжээ бараг шугаман өснө.

Эцэг зангилаа:

* Alarm-ын эцэг: Burglary, Earthquake
* JohnCalls-ын эцэг: Alarm

TabularCPD()-ийн values дээр мөр нь хувьсагчийн төлөв (0, 1), багана нь эцгийн төлөвийн хослол байна. Хамгийн сүүлийн эцэг хамгийн хурдан өөрчлөгдөнө: (0,0), (0,1), (1,0), (1,1). Үүнийг буруу бичвэл **үр дүн нь буруу, утгагүй гарна**.

Шалгах арга: print(model.get\_cpds('Alarm')) гаргаж хүснэгттэй тулгах, мөн Alarm-ын prior 0.0025 гарч байгааг харах.

## Алхам 4: Prior

| Асуулт   | pgmpy  | Хүлээгдэх |
| -------------- | ------ | ------------------ |
| P(JohnCalls=1) | 0.0521 | 0.05215            |
| P(MaryCalls=1) | 0.0117 | 0.0117             |
| P(Alarm=1)     | 0.0025 | 0.0025             |

P(JohnCalls=1) нь P(Alarm=1)-аас их байна. Учир нь Жон дохиолол дуугараагүй байхад ч 5%-ийн магадлалтай худлаа залгадаг. Жоны худлаа дуудлага нь нийт дуудлагын ихэнх хувийг эзэлдэг.

## Алхам 5: Posterior

> Шалгах: Бүх утга таарна. Хоёр хариулт нэмж тайлбарла: (1) Хоёулаа залгасан ч хулгайчийн магадлал яагаад зөвхөн 28% байна вэ? (prior 0.001-тай холбож). (2) JohnCalls = 1 ба MaryCalls = 1 хамт нотолгоо болоход нэгтэй харьцуулахад магадлал яагаад 17 дахин өсөв (0.0163 -> 0.2842)?


| Асуулт | Төрөл | Үр дүн |
| ------------ | ---------- | ----------- |
| P(B=1        | J=1)       | Diagnostic  |
| P(B=1        | J=1, M=1)  | Diagnostic  |
| P(E=1        | J=1, M=1)  | Diagnostic  |
| P(A=1        | J=1, M=1)  | Diagnostic  |
| P(B=1        | J=1, M=0)  | Diagnostic  |
| P(J=1        | B=1)       | Predictive  |

(1) Хоёулаа залгасан ч хулгайчийн магадлал 28% л байна. Учир нь хулгайчийн prior 0.001 буюу маш бага. Мөн хоёр хүн залгах нь хулгайгаас гадна газар хөдлөлт, эсвэл хоёулаа худлаа залгах боломжоор тайлбарлагдаж болно. Нотолгоо хүчтэй байсан ч prior бага бол posterior бага хэвээр үлддэг.

(2) Жон нэгээрээ худлаа залгаж болох ч Жон, Мэри хоёр хоёулаа залгах нь Alarm дуугарсан гэдэгт хамаагүй илүү хүчтэй нотолгоо өгнө. Хоёулаа дураараа худлаа залгах магадлал үржвэрээрээ маш бага тул Alarm дуугарсан магадлал (0.0025 -> 0.7607) эрс өснө, түүнтэй хамт Burglary-н магадлал өснө.

## Алхам 6: Explaining away ба хамаарал

> Шалгах: Хүснэгтийг эхлээд таамаглаад, дараа нь pgmpy-тэй тулга. Хүлээгдэх: байхгүй үед Burglary ба Earthquake хамааралгүй, Alarm мэдэгдвэл хамааралтай. JohnCalls ба MaryCalls байхгүй үед хамааралтай (хоёулаа Alarm-аас), Alarm мэдэгдвэл хамааралгүй. Burglary ба JohnCalls нь Alarm мэдэгдвэл хамааралгүй.


| Асуулт | Үр дүн |
| ------------ | ----------- |
| P(B=1        | A=1)        |
| P(B=1        | A=1, E=1)   |
| P(B=1        | A=1, E=0)   |

Газар хөдлөлт болсныг мэдэхэд хулгайчийн магадлал 0.3736-аас 0.0033 болж буурсан. Газар хөдлөлт нь дохиоллыг "тайлбарласан" тул хулгайч шаардлагагүй болсон. Alarm нь collider (B -> A <- E) тул Alarm мэдэгдсэн үед хоёр шалтгаан хамааралтай болдог.

Хамаарлын хүснэгт:


| Хос                   | Нотолгоо | Хамааралтай эсэх                         |
| ------------------------ | ---------------- | ------------------------------------------------------- |
| Burglary ба Earthquake | байхгүй   | Үгүй                                                |
| Burglary ба Earthquake | Alarm=1          | Тийм                                                |
| JohnCalls ба MaryCalls | байхгүй   | Тийм (хоёулаа Alarm-аас хамаарна) |
| JohnCalls ба MaryCalls | Alarm=1          | Үгүй                                                |
| Burglary ба JohnCalls  | Alarm=1          | Үгүй                                                |

## Алхам 7: Enumeration

> Шалгах: query('B', {'J': 1, 'M': 1}) нь 0.2842, query('J', {}) нь 0.0521. Алхам 5-ын бүх мөрийг enumeration-аар дахин гаргаад pgmpy-ийн үр дүнтэй зөрүү 10^-6-аас бага гэдгийг батал. Enumeration-ийн цогц байдлыг (хувьсагч n бол 2^n хослол) pgmpy-ийн VariableElimination-тэй харьцуулан тайлбарла.

query('B', {'J':1,'M':1}) = 0.2842, query('J', {}) = 0.0521. Алхам 5-ын бүх мөр pgmpy-тэй таарсан, зөрүү 10^-6-аас бага abs(0.28417183536439294 - p).

Enumeration нь n хувьсагчид 2^n хослол гүйлгэдэг тул хувьсагч нэмэгдэх тусам хурдан удаардаг. VariableElimination нь хувьсагчийг ээлжлэн нийлбэрлэдэг тул илүү хурдан. Энд 5 хувьсагч тул ялгаа мэдрэгдэхгүй.

## Алхам 8: Sampling

> Шалгах: P(J=1) нь 0.052 орчим. Rejection sampling-д хүлээн авах түүврийн тоо ойролцоогоор N \* P(J=1, M=1) = N \* 0.0021 (100,000 түүвэрт \~208). 1,000 түүвэрт ердөө 2 орчим түүвэр үлдэх тул үнэлгээ маш тогтворгүй. Яагаад нотолгоо ховор үед rejection sampling үр ашиггүй болдгийг тайлбарла.


| Түүврийн хэмжээ | P(J=1) forward | Хүлээн авсан түүвэр | P(B=1\| J=1, M=1) rejection |
| ----------------------------- | -------------- | ------------------------------------ | --------------------------- |
| 1,000                         | 0.0550         | 2                                    | 0.0000                      |
| 10,000                        | 0.0514         | 21                                   | 0.0952                      |
| 100,000                       | 0.0519         | 219                                  | 0.2922                      |

P(J=1) нь түүвэр нэмэгдэх тусам 0.0521 руу ойртсон. Нотолгоо (J=1, M=1) ховор тул rejection sampling ихэнх түүврийг хаядаг: 1,000-д 2, 10,000-д 21, 100,000-д 219 үлдсэн. 1,000 түүвэрт 2 л түүвэр үлдсэн тул үнэлгээ 0.0 гарч яг утга 0.2842-оос хол байсан. Иймд нотолгоо ховор үед rejection sampling үр ашиггүй.
